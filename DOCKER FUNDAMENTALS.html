Linux Administration Basics

01.2 · Running programs

Processes

A process is a running instance of a program. Linux assigns each process a PID (process ID).

List, monitor and signal processes

COMMANDS 
ps aux
ps -ef | grep nginx
top
pgrep -a sshd
kill -TERM 1234
kill -9 1234
nice -n 10 sleep 300
jobs
bg
fg
SAMPLE OUTPUT ps -ef | grep sshd
root 1020 1 0 08:20 ? 00:00:00 /usr/sbin/sshd -D ayush 2450 2200 0 09:10 pts/0 00:00:00 grep --color=auto sshd
Important: use kill -TERM PID first to request a graceful shutdown. kill -9 forcefully terminates a process and should be a last resort.
01.3 · Service management

systemctl and systemd

systemd is the service manager on modern RHEL systems. systemctl controls services and system targets.

Manage the Apache HTTP server

COMMANDS 
sudo dnf install httpd -y
sudo systemctl start httpd
sudo systemctl status httpd
sudo systemctl enable httpd
sudo systemctl restart httpd
sudo systemctl stop httpd
SAMPLE OUTPUT systemctl status httpd
● httpd.service - The Apache HTTP Server Loaded: loaded (/usr/lib/systemd/system/httpd.service) Active: active (running) Main PID: 1842 (httpd) Docs: man:httpd.service(8)

start starts now; enable configures the service to start automatically at boot. They are different operations.

01.5 · Remote access

SSH

SSH provides encrypted remote shell access to another Linux machine.

Connect and configure key-based authentication

COMMANDS 
# Connect to a remote host
ssh ayush@192.168.125.131

# Generate an SSH key pair
ssh-keygen -t ed25519

# Copy your public key to the remote host
ssh-copy-id ayush@192.168.125.131

# Check SSH service
sudo systemctl status sshd

# Check SSH server configuration syntax
sudo sshd -t
SAMPLE OUTPUT Successful connection
ayush@192.168.125.131's password: Last login: Thu Oct 30 09:10:00 2026 [ayush@rhel ~]$
Troubleshooting order: verify the destination IP and route, confirm sshd is running, check port 22 listening, inspect firewalld, then review SSH authentication and SELinux-related logs.
01.6 · Host firewall

firewalld

firewalld manages host firewall rules using zones, services and ports. A running application does not automatically mean the firewall allows remote access.

Allow HTTP traffic on port 80

COMMANDS 
sudo systemctl status firewalld
sudo firewall-cmd --get-active-zones
sudo firewall-cmd --list-all

# Open HTTP permanently in the active public zone
sudo firewall-cmd --permanent --add-service=http
sudo firewall-cmd --reload
sudo firewall-cmd --list-services

# Alternatively, open a TCP port
sudo firewall-cmd --permanent --add-port=8080/tcp
sudo firewall-cmd --reload
SAMPLE OUTPUT firewall-cmd --list-services
cockpit dhcpv6-client http ssh

A permanent rule is stored for future reloads. A runtime-only rule does not survive a reload or reboot. Use the correct active zone for the network interface.

01.7 · Mandatory access control

SELinux

SELinux applies security policies that can restrict what processes access, even when normal Linux file permissions appear to allow it.

Check status and investigate denials

COMMANDS 
getenforce
sestatus

# View SELinux file contexts
ls -Z /var/www/html

# Restore default contexts
sudo restorecon -Rv /var/www/html

# Search recent access denials
sudo ausearch -m AVC -ts recent
SAMPLE OUTPUT getenforce
Enforcing
Do not permanently disable SELinux just to fix an application. Identify the denial and correct the file context, boolean or policy configuration where appropriate.
Part 02 · Containers

Docker Fundamentals

Docker packages an application and its dependencies into an image, then runs that image as a container.

02.1 · Core concepts

Images vs Containers

Docker Image

An immutable, layered template used to create containers. It contains application files, dependencies and metadata.

docker pull nginx:latest
docker images

Docker Container

A running or stopped instance created from an image. A writable layer is added above the image's read-only layers.

docker run -d nginx
docker ps
A useful analogy: an image is like a class or template; a container is an instance created from it. Containers are isolated processes, not miniature virtual machines.
02.2 · Under the hood

Docker Architecture

Main components

ComponentRole
Docker ClientThe CLI used to send commands such as docker run.
Docker Daemon (dockerd)Provides Docker API services and manages Docker objects.
Docker REST APICommunication interface between clients and the daemon.
containerdManages container lifecycle operations beneath Docker Engine.
OCI runtime (e.g. runc)Creates and runs containers using OCI runtime specifications.
RegistryStores and distributes images, for example Docker Hub.

docker version
docker info
SAMPLE OUTPUT docker version (shortened)
Client: Docker Engine Version: 29.x API version: 1.5x Server: Docker Engine Engine: Version: 29.x containerd: Version: 2.x

Exact versions and component details depend on the Docker Engine release and installation.

02.3 · Daily commands

Build, Run and Manage Containers

Run an Nginx web server

COMMANDS 
# Download image
docker pull nginx:latest

# Run in detached mode and publish host port 8080 to container port 80
docker run -d --name web1 -p 8080:80 nginx:latest

# List running containers
docker ps

# View logs
docker logs web1

# Open a shell inside the container
docker exec -it web1 sh

# Stop and restart
docker stop web1
docker start web1

# Remove the container after it is stopped
docker stop web1
docker rm web1
SAMPLE OUTPUT docker ps
CONTAINER ID IMAGE COMMAND STATUS PORTS a1b2c3d4e5f6 nginx:latest "/docker-entrypoint" Up 10 seconds 0.0.0.0:8080->80/tcp
TEST IN A BROWSER OR TERMINAL
curl http://localhost:8080
... <title>Welcome to nginx!</title> ...
The -p 8080:80 option publishes host TCP port 8080 to container TCP port 80. Nginx must be running and listening inside the container. Host firewall rules and network infrastructure can still affect remote access.

Useful inspection commands

COMMANDS 
docker ps -a
docker inspect web1
docker stats
docker top web1
docker port web1
docker logs --tail 50 web1
02.4 · Build your own image

Dockerfile

A Dockerfile is a text file containing instructions used by Docker to build an image.

Example: static website with Nginx

Create a file named index.html:

index.html 
<!DOCTYPE html>
<html>
<head><title>My Docker Website</title></head>
<body>
  <h1>Hello from my Docker container!</h1>
  <p>This page is served by Nginx.</p>
</body>
</html>

Create a file named Dockerfile in the same directory:

Dockerfile 
FROM nginx:alpine
COPY index.html /usr/share/nginx/html/index.html
EXPOSE 80

Build and run:

COMMANDS 
docker build -t my-website:v1 .
docker run -d --name my-site -p 8080:80 my-website:v1
curl http://localhost:8080
SAMPLE OUTPUT curl
<h1>Hello from my Docker container!</h1> <p>This page is served by Nginx.</p>

Common Dockerfile instructions

InstructionPurpose
FROMSets the base image.
WORKDIRSets the working directory for later instructions.
COPYCopies files from the build context into the image.
ADDCopies files and supports additional source handling, such as local tar extraction.
RUNExecutes commands during image build.
ENVSets environment variables.
EXPOSEDocuments the port the application is intended to use; it does not publish the port.
CMDProvides the default command or arguments when a container starts.
ENTRYPOINTConfigures the executable to run when the container starts.
02.5 · Persistent data

Docker Volumes

Container writable-layer data is removed when the container is removed. Volumes let data live independently of a container's lifecycle.

Create and use a named volume

COMMANDS 
docker volume create app-data
docker volume ls

docker run -d --name volume-test \\
  -v app-data:/usr/share/nginx/html \\
  -p 8081:80 nginx:alpine

docker volume inspect app-data
docker rm -f volume-test

# The named volume remains after container removal
docker volume ls
SAMPLE OUTPUT docker volume ls
DRIVER VOLUME NAME local app-data

Bind mount example

COMMAND 
docker run -d --name site-dev \\
  -p 8082:80 \\
  -v "$PWD/site:/usr/share/nginx/html:ro" \\
  nginx:alpine

A bind mount maps a specific host path into the container. The :ro suffix makes the mount read-only inside the container.

02.6 · Container connectivity

Docker Networking

Docker networks connect containers and can provide isolation and name-based discovery.

Bridge network and container-to-container DNS

COMMANDS 
# Create a user-defined bridge network
docker network create app-net

# Start two containers on the same network
docker run -d --name web --network app-net nginx:alpine
docker run -d --name client --network app-net alpine sleep 3600

# Resolve the other container by its name
docker exec client ping -c 2 web

# Inspect and clean up
docker network inspect app-net
docker rm -f web client
docker network rm app-net
SAMPLE OUTPUT ping web from client
PING web (172.20.0.2): 56 data bytes 64 bytes from 172.20.0.2: seq=0 ttl=64 time=0.1 ms 64 bytes from 172.20.0.2: seq=1 ttl=64 time=0.1 ms 2 packets transmitted, 2 packets received

Common network drivers

DriverTypical use
bridgeConnect containers on one Docker host. User-defined bridges support container-name DNS.
hostUse the host network namespace; port publishing is generally not needed.
noneDisable normal external container networking.
overlayConnect services across multiple Docker hosts in supported configurations.
Remember: EXPOSE 80 in a Dockerfile is documentation. -p 8080:80 publishes a port. They are not the same operation.
02.7 · Image distribution

Docker Hub and Registries

A registry stores images. Docker Hub is a popular hosted registry where you can publish and download images.

Tag, log in and push an image

COMMANDS 
# Sign in (use a personal access token when appropriate)
docker login

# Tag a local image for your Docker Hub namespace
docker tag my-website:v1 YOUR_DOCKERHUB_USERNAME/my-website:v1

# Push the image
docker push YOUR_DOCKERHUB_USERNAME/my-website:v1

# Pull it on another machine
docker pull YOUR_DOCKERHUB_USERNAME/my-website:v1

# Run the pulled image
docker run -d -p 8080:80 YOUR_DOCKERHUB_USERNAME/my-website:v1
SAMPLE OUTPUT docker push (illustrative)
The push refers to repository [docker.io/yourname/my-website] v1: pushed latest: digest: sha256:... size: 1234
Replace YOUR_DOCKERHUB_USERNAME with your actual Docker Hub username. Never put passwords or access tokens in a Dockerfile, Git repository or public webpage.
03 · Apply what you learned

Mini Project: Publish Your Own Website

Build a tiny website image, run it in a container, publish the port and push the image to Docker Hub.

Project workflow

  1. Create a project folder: mkdir linux-docker-site && cd linux-docker-site.
  2. Create index.html with your own title and content.
  3. Create the Dockerfile shown in the Dockerfile section.
  4. Build the image with docker build -t my-website:v1 ..
  5. Run it with docker run -d --name my-site -p 8080:80 my-website:v1.
  6. Test it with curl http://localhost:8080 or open that address in your browser.
  7. Check logs and status using docker ps and docker logs my-site.
  8. Tag and push the image to your Docker Hub repository.

Troubleshooting questions

  • Container is running but the website does not load. Is the application listening on the expected container port?
  • Is the host port mapped correctly with -p HOST_PORT:CONTAINER_PORT?
  • Is another process already using the host port?
  • Are host firewall rules blocking remote access?
  • Do container logs show an application startup error?
  • Does the Docker daemon have enough disk space to pull or build the image?
